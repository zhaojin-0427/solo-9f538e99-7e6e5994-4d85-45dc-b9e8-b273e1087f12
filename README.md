# 河流水质数据发布平台

数据管理员每天收到站点观测 CSV，在网页上核验指定日期的数据并发布；分析人员在公开页面查看标准化明细，并下载与明细同一版本的原始文件。

## 功能

- **上传与校验**：选择发布日期、上传 CSV。逐行检查站点/指标非空、观测时刻可解析且属于所选日期、数值为有限数字、同站点同指标同时刻不重复。
- **问题阻断**：任一问题都会列出具体行号与原因，文件不会形成候选，也绝不对外可见。
- **候选版本**：校验通过后生成待发布候选，原始文件写入本地目录，标准化明细写入 SQLite；候选对外不可见。
- **发布冲突**：候选形成后，若该日期已出现更高版本号，发布旧候选会被拒绝并提示冲突，需发布最新候选。
- **发布即同版本**：发布后，明细与原始文件同属一个版本对外展示与下载；同一日期始终只有一个已发布版本，旧版本标记为 `superseded` 并从公开入口消失。
- **失败安全**：原始文件先落盘并校验 SHA-256，再提交数据库。文件写入失败不创建候选；数据库提交失败时，原先已发布的版本及其文件保持完整可用。

## 运行

### Docker Compose

```bash
docker compose up --build
```

打开 http://localhost:8000 。数据（SQLite 与原始文件）持久化在 `water-data` 卷中。

可选环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8000` | 宿主机端口 |
| `SECRET_KEY` | 开发用固定值 | 生产环境务必设置随机值 |
| `MAX_UPLOAD_BYTES` | `67108864`（64 MB） | 单文件上限 |

### 本地运行

```bash
python3 -m pip install -r requirements.txt
DATA_DIR=./data python3 -m app
```

## 页面

- `/`：已发布数据集列表
- `/datasets/<日期>`、`/versions/<id>`：公开明细（仅已发布版本）
- `/versions/<id>/download`：下载该版本的原始 CSV
- `/loads`：跨午夜总磷负荷核算（见下节）
- `/admin`：数据管理员上传、校验结果、候选列表与发布操作

## 跨午夜总磷负荷核算

分析员在 `/loads` 选择上游、下游两个断面和连续两个数据集日期，为每个断面填写：

- 流量下限与上限（m³/s）：均须大于 0 且为有限数，上限不小于下限；
- 最大采样间隔（1～6 小时）。

核算规则：

- 浓度只取两日**当前已发布版本**中的总磷值（mg/L）；两个日期的版本在同一次数据库读取事务（SQLite 快照）中取得，期间发生重发也不会混用版本。候选版本不参与计算。
- 任一日期缺少当前已发布版本时**不计算**，只提示缺失日期，不输出单日推测结果。
- 每个断面只在相邻两条**非负**读数之间线性插值，且两条读数的间隔不超过该断面的最大采样间隔；超出间隔、负值或缺失处形成缺口，不做任何外推。
- 只在**两站共同有观测支撑**的时段积分。负荷按 `3.6 × 浓度(mg/L) × 流量(m³/s)` 折算为 kg/h（即 `mg/L × m³/s × 3.6 = kg/h`），再对时长积分。
- 流量只有区间，因此各站负荷给出范围 `[3.6×Qmin×∫C, 3.6×Qmax×∫C]`。下游减上游的差额范围由下游下界减上游上界、下游上界减上游下界得到。
- 结论：差额下界 > 0 为**确认新增负荷**；差额上界 ≤ 0 为**未见新增负荷**；跨 0 或无共同支撑时段为**无法确定**。任一站点没有共同支撑时不计算负荷范围。
- 页面展示参与时段、逐段负荷与差额、窗口缺口及覆盖率；不足 48 小时时明确标注为参与时段结果，不称为两日总量。

## CSV 格式

必需四列，列名支持中英文（如 `站点/指标/观测时刻/数值`、`site/metric/observed_at/value`）：

```csv
站点,指标,观测时刻,数值
东闸断面,氨氮,2026-11-14 08:00:00,1.24
西渡断面,pH,2026-11-14 08:00:00,7.31
```

- 编码：UTF-8（可带 BOM）或 GB18030；分隔符 `,`、`;` 或制表符。
- 观测时刻支持 `YYYY-MM-DD HH:MM[:SS]`、斜杠日期与中文日期格式；不接受带时区的写法。
- 数值以 `REAL` 存储，同时保留规范化后的原文（如 `01.2400` → `1.24`）。
- 额外的列（例如 `dataset_date`）会被忽略，不影响校验。

示例文件在 `sample_data/`：`observations_2026-11-14_valid.csv`、`observations_2026-11-14_invalid.csv`。

## 数据一致性设计

- 版本号通过 `BEGIN IMMEDIATE` 事务内 `MAX(version_no)+1` 分配，并发上传不会撞号。
- 发布在单个事务中完成：旧版本转 `superseded`、新版本转 `published`，任何一步失败整体回滚。
- 原始文件按内容哈希命名（`<日期>/<sha256>.csv`）、不可变，写入后 fsync 并复核大小与哈希。
- 发布与下载都会校验 SHA-256，文件被改动或缺失时拒绝对外提供。
- 明细通过数据库唯一约束 `(version_id, site, metric, observed_at)` 兜底防重。
- 负荷核算在 `BEGIN` 打开的读事务中完成两日版本查找与读数读取，得到一致快照。
